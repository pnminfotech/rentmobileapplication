Yes. I reviewed the System Admin files you shared, and for this app I would not build the chatbot around a small FAQ list. Your bot needs to understand intent + entity + filter + time period + action, because users will ask the same thing in hundreds of ways.
Your app already spans hostel beds, residential rooms and commercial shops; tenant admission/editing; rent/payment status; vacancies; tenant shifting; leave settlement and deposit deduction; tenant documents; former-tenant restore; unit/bed management; canteen; staff/other expenses; wallet/referrals; subscription/account functions, etc. For example, your tenant flow distinguishes vacant units and property types, while leave calculates pending rent against deposit and the shift flow finds a new vacancy.

41. Confirmation-sensitive commands
There is a big difference between:
Rahul cha rent pending ahe ka?
and:
Rahul cha rent paid kar.
First is READ.
Second is WRITE.
I would classify chatbot intents into:
READ → NAVIGATE → CREATE/UPDATE → FINANCIAL → DESTRUCTIVE
Then apply confirmation rules.
For example:
Delete room 205.
Bot:
Room 205 contains 4 beds and 3 active tenants. Deleting it would affect existing records. I won't delete it without confirmation.
The same applies to tenant leave, payment changes, deleting beds/units, expense deletion, tenant restoration, etc.

One more important point

All five should resolve internally to exactly the same thing:
{
  "intent": "rent.pending",
  "filters": {
    "wing": "A"
  },
  "aggregation": "sum"
}
That is the correct direction for this application. Your existing system already has enough structured concepts—property types, active tenants, vacancies, payment status, leave settlement, shifting, documents, canteen, expenses, wallet, etc.—to build a real admin assistant, rather than a basic FAQ bot.
For implementation, I would next turn this into a developer-ready chatbot master dataset with around 300–500 canonical intents/questions × English + Marathi + Roman Marathi + Hindi + Hinglish variants, including intent, entities, API/action, confirmation_required, and example bot response. That would be directly usable for your MERN/React Native chatbot rather than just a question list.
